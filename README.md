# Adrobot — обёртка над Keitaro

Сервис на **FastAPI + SQLAlchemy** поверх Keitaro Admin API с веб-интерфейсом из двух вкладок:

1. **Создание кампании.** На входе название, гео-код страны и ID оффера. На выходе кампания в Keitaro с заданными доменом, группой и источником трафика и двумя потоками:
   - **поток 1** (`regular`, `redirect`): фильтр `country = <гео>` → 302-редирект на Google;
   - **поток 2** (`default`, `landings`): выбранный оффер, 100%.

   Если создать поток не удалось, кампания удаляется, чтобы не оставлять полусобранную.

2. **Редактор кампании.** Можно менять название, статус, домен, группу и источник кампании, а в потоке добавлять и удалять офферы с автоматическим пересчётом долей.

## Как работает редактор офферов

- **Сначала черновик, потом Keitaro.** Добавление, удаление, закрепление и возврат меняют только локальный черновик в БД. Строки подсвечиваются статусами «новый», «изменён», «будет удалён», рядом показывается прежняя доля. Кнопка **«Применить в Keitaro»** отправляет всё одним `PUT /streams/{id}`. **«Отменить изменения»** возвращает черновик к текущему состоянию Keitaro.
- **Пересчёт долей.** Сумма активных офферов всегда 100%. Закреплённые офферы сохраняют свою долю, остаток делится поровну между остальными, лишние проценты получают первые по порядку (3 оффера → 34/33/33; закреплено 50% → остальные 17/17/16). Применить черновик, где сумма не равна 100%, нельзя.
- **Закрепление.** Если ввести процент вручную, доля закрепляется. Замок снимает или ставит закрепление. «Поровну» снимает все закрепления. Сумма закреплённых долей не может быть больше 100%.
- **Удалённые офферы.** До применения удалённый оффер можно вернуть. После применения он остаётся в списке со статусом «удалён»: его можно вернуть в поток или скрыть из списка, если он удалён окончательно. Скрытые открываются через «Показать скрытые удалённые».
- **Офферы, выключенные в Keitaro** (`state: disabled`), получают 0%, их можно включить обратно.
- **История.** Каждое применение пишется в журнал с полным составом потока до и после. Любую версию можно загрузить в черновик («Вернуть как было до» или «Вернуть эту версию») и применить заново.
- **Конфликты.** Если поток изменили в Keitaro, а локальных правок нет, черновик просто подтягивает новое состояние. Если правки есть, редактор предупреждает о конфликте.

## Установка

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```bash
cp .env.example .env    # заполнить KEITARO_URL, API_KEY и DEFAULT_*
uv sync
```

| Переменная | Назначение |
|---|---|
| `KEITARO_URL` | адрес трекера, например `https://tracker.example.com` |
| `API_KEY` | ключ Admin API из админки Keitaro |
| `DATABASE_URL` | БД приложения, по умолчанию `sqlite:///./adrobot.db` |
| `DEFAULT_DOMAIN_ID`, `DEFAULT_GROUP_ID`, `DEFAULT_TRAFFIC_SOURCE_ID` | что подставлять в форму создания (необязательно, в форме можно выбрать другое) |
| `GEO_REDIRECT_URL` | куда редиректит гео-поток, по умолчанию `https://google.com/` |

## Миграции

```bash
uv run alembic upgrade head                                     # применить все миграции
uv run alembic revision --autogenerate -m "что поменялось"      # после изменения app/models.py
uv run alembic downgrade -1                                     # откатить последнюю
```

Keitaro остаётся источником правды. В локальной БД хранятся:

- `campaigns`: кампании, созданные через приложение;
- `stream_drafts`, `draft_offers`: черновики потоков (закрепления, удалённые офферы);
- `offer_changes`: журнал применённых изменений с полным составом потока до и после.

## Запуск

```bash
uv run uvicorn app.main:app --reload
```

- UI: http://localhost:8000 (прямая ссылка на кампанию: `/#campaign-<id>`)
- Swagger: http://localhost:8000/docs

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/config` | значения по умолчанию для формы создания |
| GET | `/api/refs/{domains,groups,traffic_sources,offers}` | справочники из Keitaro |
| GET | `/api/campaigns?group_id=&mine=` | список кампаний |
| POST | `/api/campaigns` | создать кампанию с двумя потоками |
| GET | `/api/campaigns/{id}` | кампания с потоками |
| PUT | `/api/campaigns/{id}` | изменить название, домен, группу, источник или статус |
| GET | `/api/campaigns/{id}/streams` | потоки кампании |
| GET | `/api/streams/{id}/draft` | черновик офферов потока (создаётся или синхронизируется из Keitaro) |
| POST | `/api/streams/{id}/draft/offers` | добавить офферы `{"offer_ids": [..]}` |
| DELETE | `/api/streams/{id}/draft/offers/{offer_id}` | удалить оффер |
| POST | `/api/streams/{id}/draft/offers/{offer_id}/restore` | вернуть удалённый оффер |
| POST | `/api/streams/{id}/draft/offers/{offer_id}/dismiss` · `/undismiss` | скрыть удалённый оффер из списка / показать |
| POST | `/api/streams/{id}/draft/offers/{offer_id}/show` · `/hide` | включить / выключить оффер (`state`) |
| PUT · DELETE | `/api/streams/{id}/draft/offers/{offer_id}/pin` | закрепить долю `{"share": 40}` / снять закрепление |
| POST | `/api/streams/{id}/draft/rebalance` | снять все закрепления и разделить поровну |
| POST | `/api/streams/{id}/draft/discard` | отменить локальные правки |
| POST | `/api/streams/{id}/draft/commit` | применить черновик в Keitaro |
| GET | `/api/streams/{id}/history` | история применений |
| POST | `/api/streams/{id}/history/{change_id}/load` | загрузить версию `{"which": "before"}` или `"after"` в черновик |

## Структура

```
app/
  main.py            приложение, обработка ошибок Keitaro, раздача UI
  config.py          настройки из .env
  db.py, models.py   SQLAlchemy
  keitaro.py         асинхронный клиент Keitaro Admin API (httpx)
  shares.py          расчёт долей (поровну, закрепления, выключенные и удалённые)
  routers/           refs, campaigns, streams (черновик, применение, история)
  static/            UI: HTML + чистый JS, без сборки
alembic/             миграции
tests/               расчёт долей и API (фейковый Keitaro, БД в памяти)
```

## Тесты

```bash
uv run pytest
```

Тесты не ходят в сеть: Keitaro подменён фейком, БД — SQLite в памяти. Проверяются создание кампании (включая откат при ошибке), черновик, закрепления, удаление и возврат, история, конфликты и валидация.
